# Error boundaries

A boundary catches an error thrown while its subtree renders and shows a fallback, instead of unmounting the whole application.

## Implementation

```tsx
"use client";

import { Component, type ErrorInfo, type ReactNode } from "react";

interface Props {
  fallback: (error: Error, reset: () => void) => ReactNode;
  children: ReactNode;
}

interface State {
  error: Error | null;
}

export class ErrorBoundary extends Component<Props, State> {
  state: State = { error: null };

  static getDerivedStateFromError(error: Error): State {
    return { error };
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    reportError(error, info.componentStack);
  }

  render() {
    if (this.state.error) {
      return this.props.fallback(this.state.error, () =>
        this.setState({ error: null }),
      );
    }
    return this.props.children;
  }
}
```

## What boundaries do not catch

- An error thrown in an event handler. That reaches `window.onerror` instead.
- A rejected promise outside a `use` or Suspense read.
- An error during server rendering, which the framework handles itself.

## Placement

One boundary at the root gives a whole-page fallback, which tells the reader nothing and loses the rest of the page. Put a boundary on each seam the UI already has: a panel, a route segment, a widget that loads on its own.
