# Error Boundaries

A boundary catches errors thrown during rendering in its subtree and swaps in a fallback instead of unmounting the entire application.

## Implementation

```tsx
"use client";

import { Component, type ErrorInfo, type ReactNode } from "react";

interface Props {
  fallback: (error: Error, reset: () => void) => ReactNode;
  children: ReactNode;
}

interface State {
  error: Error | null;
}

export class ErrorBoundary extends Component<Props, State> {
  state: State = { error: null };

  static getDerivedStateFromError(error: Error): State {
    return { error };
  }

  componentDidCatch(error: Error, info: ErrorInfo) {
    reportError(error, info.componentStack);
  }

  render() {
    if (this.state.error) {
      return this.props.fallback(this.state.error, () =>
        this.setState({ error: null }),
      );
    }
    return this.props.children;
  }
}
```

## What Boundaries Do Not Catch

- Errors thrown in event handlers — those propagate to `window.onerror`.
- Rejected promises outside of a `use`/Suspense read.
- Errors during server rendering, which fall to the framework's own handling.

## Placement

One boundary at the root produces a useless whole-page fallback. Place boundaries at the seams that already have meaning in the UI: around each panel, each route segment, each independently loaded widget.
