# Render Props

A component accepts a function and calls it with its internal state, letting the caller decide what to render.

## The Pattern

```tsx
<Toggle>
  {({ on, toggle }) => (
    <button type="button" aria-pressed={on} onClick={toggle}>
      {on ? "Enabled" : "Disabled"}
    </button>
  )}
</Toggle>
```

## When A Hook Is Better

For pure state logic with no markup of its own, a hook is simpler and avoids the nesting that render props accumulate:

```tsx
const { on, toggle } = useToggle();
```

Render props remain the right answer when the component must render something itself — a measurement wrapper, a virtualized container, a portal boundary — and only delegates part of the output.

## Avoiding Needless Re-Renders

An inline function child is a new reference on every render, so the wrapper cannot be memoized against it. If the wrapper is expensive, hoist the function or move to a hook.
