# Toast Notification Stack

A single live region renders a bounded queue of transient messages, so concurrent notifications never trample each other.

## Overview

Toasts are easy to get wrong in three ways: they announce nothing to assistive technology, they stack without a limit, and they disappear while the user is reading them. This implementation addresses all three.

## Live Region

The container is rendered once, high in the tree, with the correct ARIA roles:

```tsx
<ol
  aria-live="polite"
  aria-relevant="additions text"
  aria-label="Notifications"
  className="toast-region"
>
  {toasts.map((toast) => (
    <Toast key={toast.id} {...toast} />
  ))}
</ol>
```

Errors should use `aria-live="assertive"` in a second region, since polite announcements wait for a pause in speech.

## Queue Behavior

The reducer caps visible toasts and holds the overflow:

```typescript
const VISIBLE_LIMIT = 3;

function reduce(state: Toast[], action: ToastAction): Toast[] {
  switch (action.type) {
    case "push":
      return [...state, action.toast].slice(-VISIBLE_LIMIT * 2);
    case "dismiss":
      return state.filter((toast) => toast.id !== action.id);
    default:
      return state;
  }
}
```

## Pause On Hover

Auto-dismiss timers pause on `pointerenter` and on focus within the region. Without this, a toast containing an action button is unusable by keyboard.
