# React

Everything here has been through a real codebase. The hooks are the ones I kept
reaching for, the patterns are the ones that survived review, and the
performance notes exist because I measured something and did not want to
measure it again.

## How this is organised

Each directory holds one kind of answer:

- **hooks** — small, single-purpose hooks with the edge cases written down.
- **patterns** — ways of composing components, and when each one stops paying.
- **components** — complete implementations, accessibility included.
- **performance** — decisions backed by numbers rather than instinct.
- **state-management** — keeping state without reaching for a library.
- **testing** — what is worth asserting, and what only looks like a test.

Every note is a directory of plain files, so the code beside a note is the code
the note is about.
