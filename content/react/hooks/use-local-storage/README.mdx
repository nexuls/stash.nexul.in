# useLocalStorage Hook

Persists a piece of React state into `localStorage` so it survives reloads, while remaining safe to render on the server.

## Overview

A naive implementation reads `window.localStorage` during the initial render, which breaks server rendering and causes hydration mismatches. This version defers the read to an effect and keeps a lazy initializer for the client-only case.

## Implementation

The implementation lives beside this guide in [`use-local-storage.ts`](./use-local-storage.ts):

```typescript
import { useCallback, useEffect, useState } from "react";

export function useLocalStorage<T>(key: string, initialValue: T) {
  const [value, setValue] = useState<T>(initialValue);

  useEffect(() => {
    try {
      const raw = window.localStorage.getItem(key);
      if (raw !== null) {
        setValue(JSON.parse(raw) as T);
      }
    } catch {
      // Ignore unavailable or corrupt storage
    }
  }, [key]);

  const write = useCallback(
    (next: T) => {
      setValue(next);
      try {
        window.localStorage.setItem(key, JSON.stringify(next));
      } catch {
        // Quota exceeded or private mode
      }
    },
    [key],
  );

  return [value, write] as const;
}
```

## Cross-Tab Synchronization

The `storage` event fires in every other tab of the same origin, which makes it a cheap synchronization channel:

```typescript
useEffect(() => {
  function onStorage(event: StorageEvent) {
    if (event.key === key && event.newValue !== null) {
      setValue(JSON.parse(event.newValue) as T);
    }
  }

  window.addEventListener("storage", onStorage);
  return () => window.removeEventListener("storage", onStorage);
}, [key]);
```

## Caveats

- Values must be JSON-serializable; `Date` and `Map` require a custom reviver.
- Writes are synchronous and block the main thread, so avoid storing large payloads.
- Private browsing modes may throw on write even when reads succeed.
