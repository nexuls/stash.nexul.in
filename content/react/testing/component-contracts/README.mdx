# Component contracts

A component's contract is what callers and users can rely on. A test should cover that and nothing below it.

## In the contract

- The accessible roles, names and states it renders.
- The keyboard interactions, and where focus lands after each.
- The callbacks it calls, and their arguments.
- Its behavior at the boundaries: empty, one item, loading, error.

## Not in the contract

- Class names and inline styles.
- The shape of internal state and the order of hook calls.
- Which child components render, or how many times anything rendered.

## Querying by role

A role query asserts accessibility and behavior in one line, which is why it is the default:

```typescript
const trigger = screen.getByRole("button", { name: "Open Palette (⌘K)" });
await userEvent.click(trigger);

const dialog = screen.getByRole("dialog", { name: "Command menu" });
expect(dialog).toHaveFocus();
```

When a role query cannot find the element, that is usually an accessibility defect, not a reason to fall back to a test id.

## Focus assertions

A test for a dialog, menu or popover should assert where focus lands on open and where it returns on close. Focus restoration is the part of these components that breaks most often.
