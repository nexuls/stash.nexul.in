# Memoization rules

Memoization is a cache, and every cache costs memory plus a comparison on each render. These rules decide when that trade is worth making.

## Measure first

Open the React Profiler and confirm three things before adding a `memo`. The component re-renders, the re-render is slow, and the slowness shows on screen. Most suspected re-render problems turn out to be one expensive child rather than a cascade.

## The rules

1. **Restructure before you memoize.** Moving state down or lifting content up removes the re-render instead of making it cheaper.
2. **`useMemo` is for expensive computation or a stable reference**, not for arithmetic. Memoizing `a + b` costs more than recomputing it.
3. **`useCallback` matters only when the consumer compares.** A handler passed to a plain DOM element gains nothing.
4. **`memo` needs stable props.** A memoized component handed a fresh object literal re-renders every time, and now pays for the comparison too.
5. **Memoize the whole subtree or none of it.** A memo boundary with one unstable prop inside it is overhead and nothing else.

## A common mistake

```tsx
// The object literal is new on every render, so the memo never matches.
<ExpensiveChart config={{ height: 320 }} data={rows} />
```

Hoist the config to a module constant, or memoize it beside whatever produced `rows`.
