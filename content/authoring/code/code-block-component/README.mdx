# CodeBlock component

`<CodeBlock />` renders the same panel a fence does, with the options as props
instead of fence metadata. It exists for the few places a fence cannot reach:
code assembled from a variable, or a block generated by a component.

A fence is the better default. When the props are literals the tag is lowered to
a fence before highlighting, so the two forms produce identical output and there
is no reason to prefer the verbose one.

<CodeBlock
  code={`export function formatCurrency(cents: number): string {
  return new Intl.NumberFormat("en-US", {
    style: "currency",
    currency: "USD",
  }).format(cents / 100);
}`}
  language="typescript"
  filename="lib/currency.ts"
  highlightLines={[2, 3]}
/>

## The one real limitation

Highlighting happens at compile time. A `code` prop that can only be known at
runtime cannot be lowered to a fence, so it renders as an unhighlighted panel —
correct, copyable, but plain. If the colours matter, the code has to be literal.

<Callout type="note" compact>
  Prefer a fence; reach for the tag when a prop has to be computed.
</Callout>
