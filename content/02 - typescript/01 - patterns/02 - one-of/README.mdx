# OneOf: exclusive unions

`A | B` means *assignable to at least one of these*, not *exactly one of these*.
A value carrying the fields of both members satisfies it:

```typescript {5}
interface Electric { name: string; batteryKwh: number }
interface Petrol { name: string; tankLitres: number }

const raw = { name: "x", batteryKwh: 75, tankLitres: 50 };
const car: Electric | Petrol = raw; // no error
```

Excess property checking hides this for a fresh object literal. It stops
applying the moment the value arrives through a variable, a parse or an API
response, which is where it matters.

`OneOf` fixes the union itself by giving each member an optional `never` for
every key it does not declare, so a foreign key has no type it could hold:

<TypeMatrix
  of="const car: … = raw"
  types={["Electric | Petrol", "OneOf<Electric | Petrol>"]}
  cases={[
    {
      label: "battery only",
      code: '{ name: "x", batteryKwh: 75 }',
      verdicts: ["ok", "ok"],
    },
    {
      label: "tank only",
      code: '{ name: "x", tankLitres: 50 }',
      verdicts: ["ok", "ok"],
    },
    {
      label: "mixes both variants",
      code: '{ name: "x", batteryKwh: 75, tankLitres: 50 }',
      verdicts: [
        "ok",
        {
          status: "error",
          message: "Type 'number' is not assignable to type 'undefined'.",
        },
      ],
    },
  ]}
/>

## Implementation

It is two type aliases, in [`one-of.ts`](./one-of.ts):

```typescript title="one-of.ts"
type KeysOfUnion<T> = T extends unknown ? keyof T : never;

export type OneOf<
  Members extends object,
  AllKeys extends PropertyKey = KeysOfUnion<Members>,
> = Members extends unknown
  ? Members & Partial<Record<Exclude<AllKeys, keyof Members>, never>>
  : never;
```

`AllKeys` has to be a defaulted type parameter rather than an inline
computation. `Members extends unknown` distributes over the union, and inside
the distribution `Members` is a single member, so `keyof Members` no longer
sees the others. The parameter list resolves the key set before distribution
begins.

`KeysOfUnion` exists for the same reason. `keyof (Electric | Petrol)` gives
only the keys the members *share*, which is the wrong set.

## Cost

- **Error messages get worse.** A mixed object reports a `never`-typed
  property, not *you mixed two variants*. In a wide union the reader has to work
  out which member the compiler picked.
- **It takes an interface, not a discriminated union.** If the members already
  carry a shared literal tag, use that instead. `switch` narrowing,
  exhaustiveness checks and the error messages are all better.
- **Excess keys stay forbidden downstream.** `Partial<Record<K, never>>` means
  *absent or `undefined`*, so `{ ...petrol, batteryKwh: undefined }` passes
  while `batteryKwh: 0` does not. A partial update that spreads a real value
  for the wrong key fails to compile.

Use it when the variants have no tag to discriminate on: message shapes parsed
from an API response, mutually exclusive component props, a config object where
exactly one backend is set.
