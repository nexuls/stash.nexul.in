# Render props

A component takes a function and calls it with its internal state, so the caller decides what to render.

## The pattern

```tsx
<Toggle>
  {({ on, toggle }) => (
    <button type="button" aria-pressed={on} onClick={toggle}>
      {on ? "Enabled" : "Disabled"}
    </button>
  )}
</Toggle>
```

## When a hook is better

For state logic with no markup of its own, a hook is shorter and avoids the nesting that render props pile up:

```tsx
const { on, toggle } = useToggle();
```

Render props are still the right answer when the component renders something itself, such as a measurement wrapper, a virtualized container or a portal boundary, and delegates only part of the output.

## Avoiding needless re-renders

An inline function child is a new reference on every render, so `memo` on the wrapper never matches. If the wrapper is expensive, hoist the function out or move to a hook.
