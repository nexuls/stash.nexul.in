# Toast notification stack

One live region renders a bounded queue of transient messages, so two notifications raised at once do not overwrite each other.

## Overview

Toasts usually fail in the same few ways. They announce nothing to assistive technology, they stack without a limit, and they disappear while the reader is still reading. This implementation fixes each one.

## Live region

The container renders once, high in the tree, with the ARIA roles it needs:

```tsx
<ol
  aria-live="polite"
  aria-relevant="additions text"
  aria-label="Notifications"
  className="toast-region"
>
  {toasts.map((toast) => (
    <Toast key={toast.id} {...toast} />
  ))}
</ol>
```

Put errors in a second region with `aria-live="assertive"`, because a polite announcement waits for a pause in speech.

## Queue behavior

The reducer caps the visible toasts and holds the overflow:

```typescript
const VISIBLE_LIMIT = 3;

function reduce(state: Toast[], action: ToastAction): Toast[] {
  switch (action.type) {
    case "push":
      return [...state, action.toast].slice(-VISIBLE_LIMIT * 2);
    case "dismiss":
      return state.filter((toast) => toast.id !== action.id);
    default:
      return state;
  }
}
```

## Pause on hover

The auto-dismiss timer pauses on `pointerenter` and on focus inside the region. Without that pause, a keyboard user cannot reach the action button inside a toast before it closes.
