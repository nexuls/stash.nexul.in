# Headless data table

Keeps table behavior, meaning sorting, selection and column visibility, apart from presentation, so one model drives both a dense admin grid and a wide reading view.

## Overview

The state model is a reducer over an array of column definitions. Nothing in the model touches the DOM, so a test can drive it without rendering anything.

![Data table layout](./data-table-layout.svg)

## Column definitions

A column describes how to read and render one field, and nothing else:

```tsx
import type { Column } from "./data-table";

const columns: Column<Entry>[] = [
  { id: "title", header: "Title", accessor: (row) => row.title, sortable: true },
  { id: "category", header: "Category", accessor: (row) => row.category, sortable: true },
  { id: "updated", header: "Updated", accessor: (row) => row.updatedAt, sortable: true },
];
```

## Sorting

Sort state is one `{ columnId, direction }` pair. A click on a sortable header cycles ascending, descending, unsorted:

```typescript
function nextDirection(current: SortDirection | null) {
  if (current === null) return "asc";
  if (current === "asc") return "desc";
  return null;
}
```

Render `aria-sort` on the active header cell. Without it, a screen reader never announces that the order changed.

## Row selection

Selection is a `Set` of row ids rather than a boolean on each row. The source data stays immutable, and "select all" builds one new set instead of walking every row to mutate it.
