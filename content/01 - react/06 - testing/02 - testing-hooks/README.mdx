# Testing custom hooks

A hook has no interface of its own, so a test drives it through a component and asserts on what that component renders or calls.

## A minimal host component

```tsx
import { render, screen } from "@testing-library/react";
import { useDebounce } from "../use-debounce";

function Host({ value }: { value: string }) {
  const debounced = useDebounce(value, 200);
  return <output>{debounced}</output>;
}
```

## Controlling time

Fake timers keep a debounce or throttle test fast and deterministic:

```typescript
it("holds the previous value until the delay elapses", async () => {
  vi.useFakeTimers();
  const { rerender } = render(<Host value="a" />);

  rerender(<Host value="b" />);
  expect(screen.getByRole("status")).toHaveTextContent("a");

  await vi.advanceTimersByTimeAsync(200);
  expect(screen.getByRole("status")).toHaveTextContent("b");
});
```

Restore real timers in an `afterEach`. A leaked fake clock turns an unrelated async test into a timeout with no explanation.

## What not to assert

Do not assert on effect call counts or render counts. Both change when React changes its scheduling, so the test fails on an upgrade that broke nothing.
