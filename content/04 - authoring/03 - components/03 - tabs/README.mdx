# Tabs

Tabs are for genuine alternatives, meaning the same instruction written for a
different tool, runtime or language. The reader needs exactly one of the panels,
so stacking all of them as code blocks makes them read three snippets to find
theirs.

They are the wrong shape for sequential content. A panel a reader has to open to
know they need it is hidden content, not organised content.

## A shared choice

A `group` key ties every tab set in the document to the same selection. A reader
who picks pnpm at the top of a long guide sees pnpm in every block after it,
instead of picking it again at each one. The block above and the one below share
the `package-manager` group. Change one and the other follows.

<Tabs items={["Bun", "pnpm", "npm", "yarn"]} group="package-manager">
  <Tab value="Bun">
    ```bash noLineNumbers
    bun run build
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash noLineNumbers
    pnpm build
    ```
  </Tab>
  <Tab value="npm">
    ```bash noLineNumbers
    npm run build
    ```
  </Tab>
  <Tab value="yarn">
    ```bash noLineNumbers
    yarn build
    ```
  </Tab>
</Tabs>

## Rich panels

A panel holds whatever a document holds, including prose, lists and nested
components, not only code:

    <Callout type="tip" compact>

  </Tab>
</Tabs>

## Keyboard and semantics

The tab strip is a real `tablist`. <kbd>←</kbd> and <kbd>→</kbd> move between
tabs, <kbd>Home</kbd> and <kbd>End</kbd> jump to the ends, and the selected tab
is the only one in the tab order, so a reader is not made to tab through four
labels to reach the panel.
