# OpenTUI

[OpenTUI](https://github.com/sst/opentui) renders a component tree into a
terminal. `@opentui/core` holds the layout and paint engine, and framework
renderers sit on top of it, `@opentui/react` among them. Writing against it is
React work with the browser's guarantees removed. There is no CSS, no
subpixels, no accessibility tree, one font metric, and a canvas that is a grid
of cells the user can resize mid-frame.

Each note here is written from code that ran, and says where the approach stops
working.

## How this is organised

**Patches.** What breaks, the workaround, and the condition under which the
workaround can be deleted.

**Features.** Behaviour worth building once, such as input, focus, layout and
rendering, with what each one assumes about the terminal.

**Components.** Reusable pieces, each with the composition and keyboard model
it assumes.

A note belongs here when the answer took hours to find rather than minutes.
Where OpenTUI's own documentation already says it plainly, these notes link to
it instead of repeating it.
