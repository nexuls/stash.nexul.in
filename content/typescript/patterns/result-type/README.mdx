# Type-safe result pattern

A TypeScript signature says nothing about what a function throws, so a caller can skip the failure case and find out at runtime.

`Result<T, E>` models an operation that either succeeds with a value `T` or fails with an error `E`, as a discriminated union.

## Motivation

When a function returns `Result<T, E>`, TypeScript makes the caller check `.ok` before reading `.value` or `.error`:

```typescript
function parseConfig(raw: string): Result<Config, ConfigError> {
  try {
    const data = JSON.parse(raw);
    return ok(data);
  } catch (e) {
    return err(new ConfigError("Invalid JSON"));
  }
}
```

## Implementation

The full implementation is in [`result.ts`](./result.ts):

```typescript
export type Ok<T> = { readonly ok: true; readonly value: T };
export type Err<E> = { readonly ok: false; readonly error: E };
export type Result<T, E = Error> = Ok<T> | Err<E>;

export function ok<T>(value: T): Ok<T> {
  return { ok: true, value };
}

export function err<E>(error: E): Err<E> {
  return { ok: false, error };
}
```
